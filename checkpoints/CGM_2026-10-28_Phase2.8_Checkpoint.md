## Architecture and current endpoints

- CGM API: `https://jpcg.onrender.com/authfirst.php` (membership only).
- JPCG web runtime: PHP 8.3/Apache Docker, PDO PostgreSQL; `DATABASE_URL` stored privately in Render.
- PostgreSQL: new Neon Free project in Singapore, replacing an expired/suspended Render Free database; original old membership records were NOT automatically migrated.
- Local CGM test gateway: `http://127.0.0.1:18996` for the Windows Unity prototype. Offline mode returns synthetic results; live mode forwards ONLY email/request ID membership check to JPCG. It does NOT receive PlayPark passwords or replace BASE `anlgarden.com`.
- Local fixture port `18995` established basic TCP request/response independently of the gateway.
- The original Unity export contains `GardenUI.unity`, original graphic assets and mostly stubbed AssetRipper C# scripts.
- Existing membership endpoint returns statuses `ACTIVE`, `INACTIVE` or `ERROR` with schema/request ID/expiry fields. A membership email alone does NOT prove account ownership.

## Network observations and limitations

- Official PC and Nox BASE Android clients were observed independently owning connections to `121.52.205.124:20840` while at Garden; simultaneous ownership does not establish identical protocol or interchangeable session state.
- Observed initial login/game TCP candidates: `:18805`, `:18806`. In tested captures, several game TCP streams use 16-bit little-endian length-including-header framing.
- BASE APK `cgm.pcapng` also showed encrypted HTTPS identification for `anlgarden.com`, distinct from JPCG membership service.
- Garden port `20840` does not have the same verified framing. Prior simple XOR/opcode hypotheses were **not confirmed**.
- No captured traffic alone proves that the rebuilt Unity client has obtained a provider-authorized identity, CCU, game or Garden session. Do not log/replay account tokens or credentials.
